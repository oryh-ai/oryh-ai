# 不懂行业，凭什么自称企业 AI 专家？

*《当 Agent 开始操作企业》· 研发随笔*

“这个订单完成了。”一句很普通的话，销售、仓库和财务听到的可能不是同一件事。销售觉得客户已经确认；仓库觉得货已出库；财务要问发票和收款。若现场人员把其中一个系统状态当作全公司的“完成”，Agent 接下来推进得越快，错得可能越远。

有人说，FDE 不必懂行业，带上足够强的模型，现场问客户就行。我不信。模型能帮忙读材料，但谁知道该问什么、哪个回答还不够、哪个动作会把风险传给下游？这靠的不是行业词汇表。

## 行业经验不是会说几句行话

拿制造业的一张订单想想。销售拿到客户确认，生产已经安排，仓库却只有部分原料。系统算出缺口四公斤钢材。一个不熟业务的人可能很快说：“缺料，自动创建采购单。”可缺口不等于采购决定。有没有可替代材料？另一批订单已占了多少？供应商能不能按时送？这批生产是否允许分批交付？缺口的计算基准是按一件产品，还是按十件的配方？

这些问题会改变“下一步”。有时先调整排产，有时要核对占用，有时确实要采购。资深人员的价值，不是能背出 BOM、MRP、WMS 三个缩写，而是看见一条数据背后有哪些可能的原因和后果。

换到零售，也不能把“卖出”当成单一节点。平台订单付款、商家实际发货、顾客签收、退货期结束、平台结算到账，时间可能分开。拿今天的商品标题解释上个月的订单，也可能把后来换掉的链接内容当成当时卖出的货。不了解这些分岔，Agent 读得再快，只会更快把不同时间的事实揉成一团。

一个人不可能熟悉所有行业。正因如此，我对“学完 Agent 平台，马上能跨行业做 FDE”的广告很反感。会搭模型和接口，是工具能力；知道一笔业务错在哪个环节会产生实际损失，是长期在行业里摸出来的判断。

## 别在现场把客户当行业教材

客户可以教现场人员自己的特殊做法，却不该负责从头教他行业常识。采购负责人解释“为什么缺料不一定下单”时，是在讨论这家公司怎样办事；如果还要先从“占用和现货不是同一个数”讲起，供应商派来的“企业 AI 专家”就很难令人信服。

行业经验也不是永远正确。资深人士可能把上一家公司的习惯带过来，误以为这个行业都这样。所以真正有经验的人会把经验当作提问线索，而不是裁决书。他知道该问哪些问题、在哪些节点必须看合同和原始记录，以及自己什么时候不能拍板。

比如客户说：“发货以后，销售单就算完成。”一个懂履约的人不会立即照写规则，也不会立刻反驳。他会问：分批发货怎么办？客户拒收怎么办？后续补货是否沿用同一张单？“完成”只是销售看板不再催办，还是财务也不再对账？不同答案，会决定 Agent 能不能关闭待办、释放库存占用或提醒开票。

这些追问不只是多问几句。它们决定记录层要留下哪些事实，Agent 可以据什么推断，哪些步骤必须等人确认。若现场人员缺这个能力，他常把客户的口头总结变成系统里的一个万能状态，把真实的差异压没了。

行业老手也更容易看出“同一个词，换个环节就换了证据”。仓库说“已发”要看出库单和承运记录；销售说“已交付”可能要看客户签收；财务说“已结清”要看收款或冲销凭证。现场人员不必亲自做每张单，但如果他把三句话并成一个完成状态，后续 Agent 就没有材料解释为什么销售已完成、财务仍在追款。

## 判断可以交给 Agent，行业责任不能扔给 Agent

我们希望 AI 时代的软件别再把每一种企业做法提前写进代码。软件记订单、物料、占用、实际出库、发票和收款；金额与数量的合计由程序算。Agent 读公司规则，针对当前事实决定是催补材料、创建待办，还是建议采购。

这种分工给了客户更大的灵活性，也给现场人员更重的责任。他得知道哪些事实从旧系统导入时可能变了口径，哪些制度写得不完整，哪些建议只应列成候选而不能直接执行。模型输出“建议采购”时，他应能追问：建议基于实际缺口，还是把已占用量又扣了一遍？如果查错库存，采购行为造成的不是一句答复错误，而是钱和货的实际移动。

会操作 AI 平台的人可以协助部署，应该得到尊重。但“能连接模型”和“能为制造企业的采购链路负责”之间，不是一堂课程或一个岗位名称的距离。前者是技能，后者是经历、判断与持续承担结果。

## 先选行业，再谈 FDE

厂商若真要用 FDE 模式，先说清在哪个行业、哪一类业务里有真正懂行的人。别拿一份“我们服务各行各业”的介绍代替具体能力。客户可以问：现场负责人亲自处理过哪种业务异常？曾经在哪一步阻止错误推进？他说不清楚时，是及时找行业负责人，还是照着看似通用的流程往下推？

跨行业借鉴当然有价值，但只有知道两个行业哪些地方不同，借鉴才不会变成误用。一个资深零售人去制造现场，也要承认自己有学习区；一个制造老兵到服务业，也得重新理解“交付完成”的含义。真正的专家不会因为名片印了 FDE，就突然拥有所有行业的经验。

所以，客户选择这类人时不妨问一个比“服务过多少家企业”更难的问题：你在哪个具体业务环节曾经改变过部署方案，为什么？若回答总是“我把流程自动化了”，却说不出原先哪条记录不可靠、哪一步不能自动执行，很可能只有平台经验，没有行业判断。能诚实说明自己不熟的范围，反倒更像值得信任的专家。

做 Oryh 时，我们曾把物料缺口的计算与“要不要采购”分开：服务器算清配方、损耗、库存和缺口，Agent 再读企业实际采购规则决定后续动作。缺四公斤是事实，不是命令。现场人员如果连这两句的差别都不敏感，就不该被包装成懂企业决策的 FDE。
