# 使用手册

Oryh 是 AI 原生的 ERP/CRM：员工已经在用的 agent 就是界面，服务端只保管记录，公司的流程是工作区自己拥有的一段文字。这份手册写给从公开仓库部署了 Oryh、接下来要让它对一家公司真正有用的人。它覆盖自托管产品的完整链路：装起来、创建第一个工作区、接入 agent、把公司自己的记录装进去、以及长期运行。

它不是 <https://oryh.ai> 托管服务的手册。那个服务跑的是同一套产品，但注册、计费和平台运营方那一侧，不在你部署的东西里。

## 先理解它是什么形状

Oryh 是 headless 的。企业真正跑起来靠的那些单据 —— 员工、客户与供应商、产品、报价单、订单、进销两个方向的发票、收付款、工资、工时、报销、请假 —— 都存在这里，但**创建和推动它们的动作发生在 agent 里，不在页面上**。一个人对自己的 AI agent 说要填工时，agent 用工作区发给它的技能去做，服务端记录下这件事发生了。

于是浏览器控制台的职责比一般 ERP 的界面窄得多：它管理工作区。谁存在、谁能做什么、哪些技能发给了谁、主数据是什么、以及实际发生过什么。每个页面具体干什么，见[管理控制台](administration.md)。

开始之前有两件事值得先接受：

- **新工作区是空的，这是刻意的。** 没有员工、没有客户、没有单据。登录后第一件有用的事不是到处点，而是[接入一个 agent](connect-agent.md)。
- **「我们这儿是这么办的」大部分是文字，不是配置。** 技能是 markdown，审批路由是流程 agent 在决策时读的一份文档，状态名是你自己的词。改变行为通常是对 agent 说一句话，而不是提一个需求。
