# 管理控制台

控制台用来管理工作区。它不是干活的地方 —— 那是[日常使用](daily-use.md) —— 但它是你核对干活结果、以及处理例外的地方。

界面本身支持中英文，可在界面内切换。

## 概览（Dashboard）

工作区状态和最新概况，以及通往下面所有页面的入口。这是一个你来看一眼的页面，不是在里面办公的页面。

## 人员与权限

| 页面 | 干什么 |
|---|---|
| **用户与邀请** | 登录身份。邀请、停用、设角色。 |
| **角色与权限** | 具名的能力集合。 |
| **员工档案** | 人事记录 —— 姓名、工号、单据所指的那个人。 |

用户和员工是两种记录，任一方都可以单独存在；[初始化工作区](workspace.md)解释了为什么这件事要紧。

角色名用小写字母加下划线。能力是动词，有时带对象类型作用域。一个人的 agent 能做什么，恰好等于他的角色授予了什么 —— 由出示的凭据决定，绝不由调用方自称什么决定。

## 主数据

项目、供应商、产品与 SKU（含分类树、图片、物料清单）、销售渠道、店铺、设施、资源，都支持筛选和分页。客户有独立页面，带联系人与价格协议。这些是核对用的页面；批量导入交给 `oryh-master-data`。

## 对象与规则

| 页面 | 干什么 |
|---|---|
| **对象类型与流程** | 字段规则、状态流程、工作流版本 —— 内置单据和你自定义的类型一视同仁。 |
| **业务对象** | 工作区里的每一条记录，带详情视图。 |

内置实体必须提供状态机定义；你自己的类型需要字段 schema 和一套用你自己词汇写的生命周期。两者都属于管理员范围，也都有权限门：没有工作区配置权限的账号会被明确告知，而不是看到一个坏掉的页面。自定义类型不能用系统已有对象的名字（`customer`、`product`、`quote`……）；服务端会拒绝并指出真正的集合。

## 活动记录

| 页面 | 干什么 |
|---|---|
| **待办** | 人工工作队列 —— 工作空间的，和我的。 |
| **审批记录** | 完整且不可变的审批历史。 |

审批记录是只读审计视图，而**读它本身就是一项权限**。没有这项权限的账号会被告知权限不足，而不是看到一张空表。

「我的待办」需要有一份员工档案作为主语。没有关联员工记录的账号会被明确告知这一点 —— 这是一个真实状态，不是错误。

## 技能、分发与凭证

| 页面 | 干什么 |
|---|---|
| **Skill 文件包** | 有哪些技能，以及每一个触达了谁。 |
| **访问凭证** | API 密钥。签发、打标签、停用。 |
| **流程 Agent** | 无人值守的流程驱动有没有推动什么，以及还有多少在等。 |

技能页面存在的意义是一眼回答一个问题：**这个技能触达了谁？** 一个定向到具名人员、却一个人都没指定的技能，会显示为 **定向 · 无人** —— 这是一个真实状态，而且值得抓出来，因为它看起来配好了，实际谁也没触达。

访问凭证页是你在不需要找回首次启动那把密钥的前提下签发新 agent 密钥的地方，也是密钥泄露时停用它的地方。一把密钥不可用的原因可能与密钥本身无关 —— 它的用户被停用了，或者从未激活 —— 页面会区分这些情况，而不是笼统报一个失败。

## API

控制台是照着同一份你也能读的契约编译的：

- `/redoc` —— 由 schema 生成的 API 文档
- `/openapi.json` —— 契约本身

控制台能做的任何事，agent 都能做。
